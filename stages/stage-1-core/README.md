# Этап 1 — ядро процессов

Первый работающий срез модуля: шаблон процесса с правилами маршрутизации, запуск заявки по шаблону,
задача на роль и её выполнение. Всё остальное (SLA, события, аналитика, операции над процессом)
появляется на следующих этапах.

## Что уже есть

| Область | Что реализовано |
|---------|-----------------|
| Шаблоны процессов | Черновик → правила маршрутизации → публикация → архив; версия на каждый код (REQ-02-002) |
| Маршрутизация | Одно условие на правило (`поле оператор значение`), операторы `EQ NEQ GT GTE LT LTE`, правила проверяются по возрастанию приоритета, побеждает первое подошедшее (REQ-02-004) |
| Процессы | Запуск по опубликованному шаблону, статусы `Не запущен → Выполняется → Завершён / Отменён`, фильтр и поиск по бизнес-ключу |
| Задачи | Создаются маршрутизацией на роль, выполняются; выполнение задачи двигает процесс на следующий шаг или завершает его |
| Доступ | Keycloak (OIDC), роли из токена, `@PreAuthorize` на каждом методе API |
| Интерфейс | Своя форма входа, реестр процессов, реестр задач, экран шаблонов |

## Чего ещё нет (появится дальше)

- SLA, сроки, эскалация, календарь рабочего времени — **этап 2**
- Условия из групп `AND/OR/NOT`, операторы `IN`, `CONTAINS`, `EXISTS` — **этап 2**
- Доменные события, Kafka, outbox, журнал событий процесса — **этап 2**
- Пауза/возобновление, отмена с закрытием задач, подпроцессы, переназначение — **этап 3**
- Модель видимости по организации и участию, аналитика, выгрузки CSV — **этап 3**

## Запуск

```bash
# 1. инфраструктура (Postgres + Keycloak)
docker compose up -d postgres keycloak

# 2. бэкенд
cd backend/workflow-service
mvn -DskipTests package
java -jar target/workflow-service-1.0.0.jar --server.port=8090

# 3. фронтенд
cd frontend/workflow-ui
npm install
npm run dev      # http://localhost:5173
npm run seed     # демо-шаблоны и заявки
```

Учётные записи те же, что и в остальных этапах: `admin1/admin123`, `manager1/manager123`,
`coordinator1/coordinator123`, `analyst1/analyst123`.

У каждого этапа своя схема базы, поэтому **перед переключением на другой этап уберите том**:
`docker compose down -v`.

## Тесты

```bash
cd backend/workflow-service && mvn verify     # 13 модульных + 6 интеграционных (Testcontainers: Postgres)
cd frontend/workflow-ui && npm run build && npm run lint
cd frontend/workflow-ui && npm run e2e        # Playwright: нужен поднятый и засеянный стенд
```

Что проверяется:

- **Модульные** — вычисление условия маршрутизации (равенство, числа, отсутствующий атрибут,
  нечисловые операнды у `GT`), выбор правила по приоритету, переходы статусов процесса и задачи.
- **Интеграционные** (реальный Postgres) — золотой путь «шаблон → правило → публикация → запуск →
  выполнение задачи → процесс завершён», отказ публиковать шаблон без правил (409), отказ запускать
  по неопубликованному шаблону (409), отказ запускать заявку, под которую не подошло ни одно правило
  (422), запрет запуска для роли ANALYST (403), отказ без токена (401).
- **E2E** — тот же золотой путь в браузере и сборка шаблона администратором.
