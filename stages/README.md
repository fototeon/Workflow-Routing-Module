# Этапы разработки модуля

Модуль собирался в три захода. В каждой папке лежит самостоятельный, работающий срез проекта на
конец соответствующего этапа — со своим бэкендом, фронтендом, тестами, миграциями и compose-файлом.
Каждый этап можно поднять и погонять отдельно.

| Этап | Папка | О чём он |
|------|-------|----------|
| 1 | [`stage-1-core`](stage-1-core/) | Ядро процессов: шаблоны, правила маршрутизации, запуск заявки, задачи |
| 2 | [`stage-2-routing-sla`](stage-2-routing-sla/) | Деревья условий, SLA и эскалация, доменные события и журналы |
| 3 | [`stage-3-operations`](stage-3-operations/) | Операции над процессом, модель доступа, аналитика и выгрузки |

Третий этап — это итоговое состояние модуля; в корне репозитория лежит он же, и именно он
развивается дальше. Папки этапов — снимки, а не рабочие копии.

## Что происходит от этапа к этапу

| | Этап 1 | Этап 2 | Этап 3 |
|---|---|---|---|
| Шаблоны и версии | ✅ | ✅ | ✅ + каталог со статусами и числом правил |
| Условие правила | одно сравнение | дерево `AND/OR/NOT`, `IN`, `CONTAINS`, `EXISTS` | то же |
| Запуск процесса и задачи | ✅ | ✅ | ✅ |
| SLA, календарь, эскалация | — | ✅ | ✅ + пауза останавливает часы |
| События в Kafka, outbox, DLQ | — | ✅ | ✅ + намерения на уведомления |
| Журнал процесса и изменений шаблона | — | ✅ | ✅ |
| Входящий `RequestAccepted` | — | ✅ | ✅ |
| Пауза, отмена с задачами, подпроцессы | — | — | ✅ |
| Переназначение на человека или роль | — | — | ✅ |
| Модель видимости заявок | — | — | ✅ |
| Аналитика и выгрузки CSV | — | — | ✅ |
| Тесты бэкенда | 13 + 6 | 37 + 8 | 39 + 52 |
| Тесты фронтенда (Playwright) | 2 | 4 | 14 |

## Как запустить любой этап

```bash
cd stages/<папка этапа>
docker compose up -d postgres keycloak        # на этапах 2 и 3 ещё kafka
cd backend/workflow-service && mvn -DskipTests package
java -jar target/workflow-service-1.0.0.jar --server.port=8090
cd ../../frontend/workflow-ui && npm install && npm run dev && npm run seed
```

Подробности — в README внутри каждой папки.

**Важно:** у каждого этапа своя история миграций Flyway, поэтому они не должны делить одну базу.
Перед переключением на другой этап уберите том предыдущего: `docker compose down -v`. Compose-проекты
у этапов тоже разные (`workflow-stage-1/2/3`), так что одновременно поднятые стенды не перетирают
друг друга — но порты (5432, 8081, 9092, 5173) у них общие, поэтому поднимать больше одного этапа
сразу не получится.
